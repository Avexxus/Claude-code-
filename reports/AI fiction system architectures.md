# Commit story memory only after checks

**Summary.** Across the academic, commercial and engineering notes, the most transferable idea is that a fiction engine should keep its world facts in typed, ID-keyed records, and let only checked scenes write to them. Four independent lines of work (ConWriter, MAGNET, InkOS, and the Inkfluence record design) converge on this, and the two that ran ablations show the largest measured consistency gains. Rolling summaries, text-only scratchpads and LLM judges used for counting or error recall are the weakest parts of the field. All evidence is single-paper, vendor-reported, or abstract-level; nothing has been replicated, and no source tests grimdark fiction, novel-length output (80k+ words), or reader simulation validated against real readers. The ten patterns below are ranked by how directly they fix the failures our engine is most exposed to: continuity drift, characters who know things they should not, and scenes that break the plan. Where the notes conflict, the conflict is stated in the caveats section.

## The ten most transferable patterns, ranked

1. **Typed, always-on story bible and running state.** A structured record of the world, cast, objects, timeline and who-knows-what is sent on every call, with recent prose kept verbatim only in small amounts. Inkfluence sends its bible before each chapter and keeps a generated running record with five typed entry types tagged by source chapter; Sudowrite's Story Bible uses explicit field-dependency rules; InkOS treats structured state as the authority and a search index as only a projection; autonovel keeps `canon.md`, `state.json` and `characters.md`. Strength: **PROMISING** for fiction (five independent tools use it; none has a controlled comparison against a plain summary). Engineering notes label the underlying practice **PROVEN** as an operational pattern (Anthropic's lead agent saves its plan to external memory because context beyond about 200k tokens gets truncated). Sources: [Inkfluence](https://www.inkfluenceai.com/learn/how-inkfluence-ai-keeps-a-book-consistent), [InkOS](https://github.com/Narcooo/inkos), [Anthropic, multi-agent research system, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system). **Copy:** typed records with IDs for who is where, injuries, objects, money, timeline, and who knows what; a chapter summary kept alongside the record. **Avoid:** a rolling summary as the only memory, and hand edits that do not reach the generated record (a limit Inkfluence itself states).

2. **Commit to memory only after a check passes.** A scene writes to memory only if it has zero blocking violations, and a rejected scene leaves memory unchanged. ConWriter does this with static and dynamic memory, and MAGNET commits world-state updates only for the action the narrator selected. In ConWriter's ablation on DeepSeek-V4-Flash at 3K, the full system scored **0.1335** consistency errors per 10k words against **0.6843** without structured validation, though that metric is judge-based. Strength: **PROMISING**. Sources: [ConWriter, arXiv 2608.05169, v1 2026-05-27](https://arxiv.org/abs/2608.05169), [MAGNET, arXiv 2607.00918, v1 2026-07-01](https://arxiv.org/abs/2607.00918). **Copy:** the commit rule itself, and the rule that a failed repair leaves memory untouched. **Avoid:** using the same model family to both write and judge the commit check.

3. **Scene transition contracts: preconditions, postconditions and forbidden changes.** Each scene carries data, not prose instructions: what must hold before it runs (Pre), what it changes (Post), and what it must not change (Forbid). ConWriter's transition operator checks feasibility before drafting. Strength: **PROMISING** (single paper; ConWriter's ablation covers the verification stack as a whole, not this contract alone). Source: [ConWriter, arXiv 2608.05169](https://arxiv.org/abs/2608.05169). **Copy:** add Pre, Post and Forbid fields to each scene card and check them before drafting. **Avoid:** writing forbids only as prose the writer may ignore; the paper treats them as checkable data.

4. **Chapter-stamped entity and event graph, with retrieval by entity.** Memory is stored as `<subject, action, object, chapter>` quadruples, retrieved by entity and then filtered by relevance. DOME's temporal graph cut its conflict rate to **0.56** from **4.52** without the memory module (20 premises, 2024 generator). CreAgentive's recall and thread agents, which read past events and foreshadowing, dropped its composite score from **8.48** to **7.93** when removed (its Table 2 gives 8.28 for the full system; see caveats). Strength: **PROMISING**. Sources: [DOME, arXiv 2412.13575, v1 2024-12-18](https://arxiv.org/abs/2412.13575), [CreAgentive, arXiv 2509.26461, v1 2025-09-30](https://arxiv.org/abs/2509.26461). **Copy:** chapter-stamped facts with entity keys, so the continuity check can ask "what is true about X at chapter N". **Avoid:** DOME's ranking over ConWriter's, because ConWriter re-tested DOME with newer models and found it worse than direct generation in several cells. DOME also cost about 200 API calls and about 4 hours for a 7,000-word story.

5. **Visibility-scoped knowledge on every fact.** Each fact carries the set of characters who can know it, and character-facing context includes only those facts. ReverieMem stores five-element SPOCV tuples with a visibility set and reports **KBF 73.3** against **38.7** for BookWorld on its own eight-novel benchmark (4,386 questions). An ICLR 2026 MemAgents poster reports a **73%** reduction in known-information forgetting using "already knows" markers, from one deployment with one author. Strength: **PROMISING**. Sources: [ReverieMem, arXiv 2606.25632](https://arxiv.org/html/2606.25632), [ICLR 2026 poster, "Epistemic Memory Failures"](https://iclr.cc/virtual/2026/10021229). **Copy:** a visibility field on each fact, and an "already knows" marker in the character's context. **Avoid:** treating the 34.6-point margin as settled, since the authors say benchmark items were validated by themselves alone. ReverieMem explicitly does not cover multi-witness contradictions, information-asymmetric mysteries or unreliable narrators, which are central to grimdark secrets.

6. **A critic gate on each character action before it becomes a beat.** Each character agent proposes an action; a critic checks relevance, specificity and consistency, and either returns revision feedback or accepts and emits world-state updates. MAGNET's critic loop regenerates an action until it is accepted or a revision cap is hit. Its ablation at 20 pages: no critic **109.0** editor annotations against **84.0** for the full system (lower is better), and rubric **78.1** against **82.6**. Strength: **PROMISING** (single paper; the baselines are single-model prompting, StoryBox and StoryWriter, which are weak by current standards). Source: [MAGNET, arXiv 2607.00918](https://arxiv.org/abs/2607.00918). **Copy:** the accept-or-revise loop with a hard cap, and the critic being the only path to state updates. **Avoid:** the margin over older baselines as a margin over strong modern pipelines; MAGNET's evaluators come from the same model families as its generators.

7. **Verify, then repair with a repair spec and a retry budget.** A failed scene goes to sentence-level repair, and the repair request states the violated constraints, the evidence, the content to keep, and the forbidden changes. If repair fails within the budget, the scene is rejected. ConWriter's consistency-error rate (CED, errors per 10k words) fell by **50.6% to 87.5%** against direct generation across nine model-and-length cells. Strength: **PROMISING**. Source: [ConWriter, arXiv 2608.05169](https://arxiv.org/abs/2608.05169). **Copy:** the four-part repair spec as a fixed template, and a hard retry budget. **Avoid:** repeated feedback loops in general. ConWriter's own limits note that repeated feedback can conflict with length control, and that some strong models are less repair-compliant.

8. **Scripts for mechanical checks, models for judgment.** Counting, citation presence, name collisions, timeline arithmetic, banned-term scans and schema validation run as code between stages. Models handle whether a scene does what its plan says, whether a motive holds, and whether the reading experience works. Anthropic recommends programmatic checks between chained steps, and autonovel's `evaluate.py` combines a mechanical scorer (banned words, clichés, sentence uniformity) with a separate LLM judge. Strength: **PROVEN** as vendor guidance for the scripts; **PROMISING** for autonovel's specific scorer, whose validity is unmeasured. Sources: [Anthropic, building effective agents, 2024-12-19](https://www.anthropic.com/engineering/building-effective-agents), [autonovel](https://github.com/NousResearch/autonovel). **Copy:** word counts, cite checks and name-ledger checks as scripts that block a stage on failure. **Avoid:** asking a model to count words or check cites; the notes treat that as a known failure.

9. **Frozen plan, sequential prose, checkpoint and resume.** A single plan file that every worker reads, a run log with stage status, outputs keyed by scene and stage ID, and resume from the last completed stage rather than from the start. Anthropic reports that its production system resumes from the point of error with retries and regular checkpoints. Strength: **PROVEN** as a production practice (Anthropic, self-reported); **PROMISING** for generalisation. Cognition's account of a conflict between parallel subtasks (a background and a bird that did not match) is a single worked example. Sources: [Anthropic, multi-agent research system, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system), [Cognition, "Don't Build Multi-Agents", 2025-06-12](https://cognition.com/blog/dont-build-multi-agents). **Copy:** the frozen plan, the run log, and idempotent writes to fixed paths. **Avoid:** parallel prose writers with no shared decision log. Anthropic's +90.2% result is on read-heavy search, which parallelises well, and the notes flag that it may not transfer to sequential fiction.

10. **Planned failure per beat, and a tension check.** Each beat is an attempted action that fails, with the failure reason and decreasing likelihood of success, plus clues planted early. Xie and Riedl's iterative planning method beat a ChatGPT baseline on suspense in **84.9%** of human pairwise judgments (30 pairs, 90 participants). Spoiler Alert offers a measurement: its 100-Endings "no-rate" for human New Yorker stories averages **0.765** against **0.630** for the top ten LLMs on EQ-Bench, so models are more predictable. Strength: **PROMISING**. Sources: [Xie and Riedl, arXiv 2402.17119, v1 2024-02-27](https://arxiv.org/html/2402.17119v1), [Spoiler Alert, arXiv 2604.09854, v1 2026-04-10](https://arxiv.org/html/2604.09854v1). **Copy:** the planned failure per beat, the clue plan, and a forecaster-style check on whether a draft is too predictable. **Avoid:** using predictability as a tension score on its own (the authors' own caveat). The Spoiler Alert pipeline raised late no-rate for all three models tested, but lowered rubric scores for two of three, so the gain in unpredictability came with a quality cost on some models. Xie and Riedl used a gpt-3.5-era model on short stories.

Two patterns did not make the top ten but are worth recording. Prompt caching with a stable prefix is the largest cost lever (see the cost section). The five-category, 19-subtype error taxonomy from ConStory is the most usable checker vocabulary in the notes and is covered under checker design.

## The state store and memory pattern

The engineering notes treat state as an external, typed store rather than a summary. Anthropic's context-engineering guidance (**PROVEN as guidance from a primary source**) says the goal is "the smallest set of high-signal tokens", and that compaction is safe for chat history but not for decisions, rulings or the scene-card plan, which must be persisted outside any summary ([Anthropic, effective context engineering, 2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Two vendor memory systems report gains: Mem0 claims a **26%** relative improvement over an OpenAI memory baseline on LOCOMO, and **91%** lower p95 latency than full context ([Mem0, arXiv 2504.19413, 2025-04-28](https://arxiv.org/abs/2504.19413)); Zep reports Deep Memory Retrieval of **94.8%** against **93.4%** for MemGPT ([Zep, arXiv 2501.13956, 2025-01-20](https://arxiv.org/abs/2501.13956)). Both are vendor-authored and checked only at abstract level, and neither tests long-form fiction. No controlled head-to-head of structured state against a plain summary in long-form generation was found, which is the most important gap for our design. For our purposes the practical split is: the bible, brief, scene cards and continuity ledger are files or rows with IDs, and anything a model needs for voice comes in as verbatim text for the immediate scene only.

## Checker design: scripts or models

The evidence supports splitting checks by what they measure. Scripts should own word counts per scene and chapter, required cite format, name collisions against the name ledger, timeline and date arithmetic, banned-term and forbidden-phrase scans, and JSON schema validation. These are cheap and deterministic, and a model is unreliable at them. Models should own whether a scene does what its plan says, whether a character's motive holds, whether a reader's experience works, and voice notes.

For error detection, the ConStory benchmark gives the best vocabulary. Its taxonomy has **five categories and 19 subtypes** (timeline and plot logic, characterization, world-building, factual and detail, narrative and style), and it normalises errors per 10,000 words ([ConStory-Bench, arXiv 2603.05890, v1 2026-03-06](https://arxiv.org/abs/2603.05890)). Its checker, an o4-mini pipeline, scored **recall 0.550 and precision 0.884** on 1,000 injected errors, so it misses nearly half of what is planted. The benchmark's own finding that error count grows with length (correlation 0.478 for Claude-Sonnet-4.5, 0.973 for DeepSeek-V3.2-Exp) means every checker score should be length-normalised. Flawed Fictions shows the same length effect in detection: the correlation between word count and detection score is negative for all 14 models tested ([Ahuja, Sclar and Tsvetkov, arXiv 2504.11900, 2025-04](https://arxiv.org/html/2504.11900v1)). Judges also carry documented biases. "Justice or Prejudice" lists 12 potential biases and reports that significant ones persist even in advanced models, but the abstract gives no effect sizes ([arXiv 2410.02736, 2024-10-03](https://arxiv.org/abs/2410.02736)). Anthropic's own research judge, a single call scoring a rubric from 0.0 to 1.0 with pass or fail, was the most consistent design it tested, and it worked best where the answer was clear ([Anthropic, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system)). None of the notes contains a calibration set for judges on long-form fiction.

## Revision loops: what helps and what adds churn

The ablations that show gains all share one feature: a gate on writes, with memory the writer reads back. MAGNET's critic gate, ConWriter's verify-and-repair with commit-on-zero, DOME's memory module and CreAgentive's recall agents each show a measured drop when removed. These are the revision mechanisms worth keeping. Churn shows up in three places. Agents' Room's plan-only variant produced 856 words and underperformed, so a planning stage with no check does not reliably help. ConWriter found that repeated feedback can fight length control. The Spoiler Alert pipeline lowered rubric score on two of three models while raising late unpredictability on all three. Every system caps its retries, and no paper sweeps the cap, so the right number of revision rounds is unknown. autonovel's thresholds (a foundation score above 7.5, a chapter score above 6.0) are design parameters with no calibration shown, and its plateau stop has no measured effect in its README. Revision budgets should therefore be fixed, logged, and tested on our own gold set rather than set from any published figure.

## Reader simulation: what is validated and what is not

What is validated is judge agreement with humans on coarse measures. Agents' Room's LLM pairwise judge agreed with humans at **ρ = 0.62** across systems (N=45) but only **ρ = 0.41** across items (N=9,900), with self-consistency of **90.2%**; its human raters reached Fleiss κ 0.46. MAGNET's LLM editors agreed with human annotations **82.5% to 85.0%** of the time. StoryScope's LLM feature annotation reached κ 0.84 with humans, though on only 12 stories ([StoryScope, arXiv 2604.03136, v1 2026-04-03](https://arxiv.org/html/2604.03136v1)). The pattern is consistent: judges track humans on system rankings and fail on single items.

What is not validated is most of what passes as reader simulation. Synthetic Reader Panels report positivity bias, recency bias and an "articulation premium" (better-written pitches score higher), and they have no validation against real readers or sales; its anti-slop detector has no reported accuracy ([Zimmerman, arXiv 2602.14433, v1 2026-02-16](https://arxiv.org/html/2602.14433v1)). CreAgentive's human raters were five self-described literature enthusiasts. autonovel's four-persona reader panel has no published metrics. No paper in the set reports a reader-simulation method validated against real readers' ratings over time. Our reader-panel and cold-reader roles therefore have no evidence behind them, and should be used only for relative ranking within a single run, with a human check before any decision rests on them.

## Cost and rate-limit handling

Caching is the clearest cost lever, and its pricing and mechanics are documented by the vendor. Cache reads cost **0.1×** base input by default, 5-minute cache writes cost **1.25×**, and 1-hour writes cost **2×**; some newer models have lower read multipliers listed on the same page. Cache prefixes are ordered tools, then system, then messages, and a change at one level invalidates every later level. Shorter prompts than the model's minimum are silently not cached, and the minimum is model-dependent (512 tokens for Haiku 5.5, Opus 5.5 and Sonnet 5.5) ([Anthropic, prompt caching, undated, read 2026-11-22](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). Cache reads do not count toward input-tokens-per-minute limits ([Anthropic, rate limits, undated, read 2026-11-22](https://platform.claude.com/docs/en/api/rate-limits)). The practical rules are: keep the tool list identical across stages, put timestamps and run IDs after the stable block, and use the 1-hour cache for stages that run apart in time.

The cost of the research pipelines is real and measured in calls. ConWriter uses **53 to 80 API calls** per story against **10 to 27** for direct generation, and about **1.16M** tokens against **376K** for Qwen3.5-Plus on one task. CreAgentive reports **$0.015 to $0.15 per chapter** (its Table G.1). Anthropic reports multi-agent runs using about **15×** the tokens of chat (self-reported). For rate limits, the vendor page distinguishes three failures. A 429 with a `retry-after` header should be honoured. A `ramp_limit_exceeded` error means usage rose too fast, so the fix is to rise by at most one step per minute. An `enforced_spend_limit_reached` error has no `retry-after` and retries will not succeed, so the run should halt and checkpoint ([Anthropic, rate limits](https://platform.claude.com/docs/en/api/rate-limits)). The Message Batches API is **50% off**, most batches finish within an hour, and batches are not subject to ramp limits, which makes it the right home for offline readers and continuity scans ([Anthropic, batch processing, undated, read 2026-11-22](https://platform.claude.com/docs/en/build-with-claude/batch-processing)). Note that the notes' own illustrative cost arithmetic for a 100k-token bible was not checked against live prices, so no dollar figure from it is used here.

## Human-in-the-loop gate placement

The notes contain little direct evidence on where to place human gates. Anthropic reports that human testers caught hallucinations, system failures and source-selection bias that its judge missed, which supports keeping a human check on decisions the judge cannot see ([Anthropic, 2025-06-13](https://www.anthropic.com/engineering/multi-agent-research-system)). The engineering notes' inference, which has no published support, is to place humans where a wrong decision is expensive to undo: canon and plans, not every scene. Inkfluence's stated limit points the same way from the other side: finished chapters are not rewritten, so an error that is accepted into the record persists until the chapter is regenerated. That argues for the gate sitting before the state commit, which connects to pattern 2. Our two existing gates, the brief and the plan digest, fit this placement. The one change the evidence suggests is that the continuity keeper's write after approval should be preceded by the automated checks, so that the human sees a checked change rather than a raw one.

## What this means for our engine

The table maps the patterns onto the roles that exist in `.claude/agents/`. The mapping uses the frontmatter description of each role; I did not read the role bodies, so the fit should be confirmed against them.

| Engine role | Current job (from its description) | Pattern(s) | Evidence and gap |
|---|---|---|---|
| world-slicer | Pulls canon into a story bible slice, tags LOCAL inventions | 1, 5 | Typed slice is supported. Visibility tags are not mentioned, so add a visibility field per fact (gap: no evidence beyond ReverieMem and the ICLR poster). |
| cast-builder, conflict-mapper | Character dossiers; offscreen actions per phase | 5, 10 | Offscreen actions are a natural source of planned failure. Who-knows-what per character is the gap. |
| scene-carder | Scene cards (goal, conflict, disaster, stress, value shifts) | 3, 10 | Add Pre, Post and Forbid fields (ConWriter). Card fields are supported by evidence only through ConWriter's single paper. |
| plan-auditor | Audits plan and draft against canon, logic, coincidence, payoff | 8 | Split its checks: scripts for names and timeline, model for motive and logic. |
| story-writer | Drafts and revises prose from cards | 7, 9 | Keep drafting sequential. Use the repair spec as the revision template. |
| sense-checker | Checks each beat against everything approved before it | 2, 4, 6 | Closest to MAGNET's critic gate. Its output should gate the beat's state commit. |
| character-sim | Plays each main character before a key scene | 6 | Analogous to MAGNET's character agents, but run before drafting rather than per action. No evidence for this exact design. |
| continuity-keeper | Updates running state after each approved chapter | 1, 2, 5 | Matches the Inkfluence record and InkOS authority rule. It should write only through the checks, not after approval alone. |
| payoff-keeper | Seed and rule ledger after every beat | 1, 4 | Typed ledger with chapter stamps (DOME). Earned-payoff judgment is a model task with no evidence in the notes. |
| forecaster | Tension check by predicting ahead of each scene break | 10 | Spoiler Alert's no-rate is the closest measure. Use it as a diagnostic, not a gate, because predictability alone misleads. |
| dev-critic, judge | Lore, logic and craft critique; rules disputes | 6, 8 | Judge calibration is the gap: no gold set exists, and judges are weak at item-level calls. |
| story-guard | Checks that a line edit changed only the writing | 2, 8 | Make this a script diff plus a model check. |
| word-watch | Finds tics and overused words | 8 | Counting is a script; tic detection is a model task. The notes give no evidence that polish passes help consistency. |
| line-editor, dialogue-editor | Named polish passes; dialogue voice | none | No evidence in the notes that polish passes improve or harm consistency. Measure before trusting them. |
| reader-panel, cold-reader | Synthetic and cold reading of finished chapters | none (caution) | Weakest evidence in the set. Use for relative ranking only, with a human check. |
| originality-check | Trope and near-copy check | none | No evidence in the notes. StoryScope's narrative-feature approach is a diagnostic lead, and its own result says raw-text detectors beat it. |

**Gaps with no evidence in the notes.** Five matter most for our engine. First, no controlled test of structured state against a plain summary in long-form generation. Second, nothing on grimdark, and nothing on tone or dread as a measurable target: all evidence is on general narrative quality, and Suspense explicitly uses Western narrative theory. Third, nothing at novel length (80k+ words); almost all systems stop at 10 to 100 pages or about 7,000 words, and our serialised books will run longer. Fourth, no reader-simulation method is validated against real readers over time, and no paper sweeps revision rounds. Fifth, no evidence on visibility across multiple witnesses or unreliable narrators, which the authors of ReverieMem list as future work. The practical response is to build a small gold set from our own approved chapters, with human labels, and measure each checker and reader role against it before relying on it.

## Caveats and what's unverified

**Evidence strength and labels.** No finding in the notes has been replicated; every paper is single-author or single-group work. The two note sets use the labels differently. The academic notes define "proven" as a measurement reported across several models or datasets within one paper, and state that strictly no finding reaches that bar, so their "Proven (benchmark-level)" label means strong but unreplicated. The engineering notes define PROVEN as a measured result or stable API behaviour from a primary source, which includes vendor self-reports such as Anthropic's internal evals. This report carries each label as its notes assign it, and the two scales should not be compared directly.

**arXiv numbers to check against the PDFs.** Every arXiv figure here was extracted through a summarizing fetch tool from HTML or abstract pages, and the notes flag that extractions were internally inconsistent in several places. Check each figure against the PDF before it goes into a codex or any shared document. Several appendices were not read at all: ConWriter's appendices were partly read, and Agents' Room was read only to about 100k of 170k characters. Appendix-only results may be missing for ConStory-Bench, DOME, Flawed Fictions, Spoiler Alert, StoryScope, the fair-play paper and Suspense. Three systems came up in search but were not read: StoryWriter (arXiv 2506.16445), SuperWriter-agent (arXiv 2506.04180) and WSE-bench (arXiv 2608.15654).

**Conflicting figures, stated where they occur.**
- CreAgentive: Table 2 gives 8.28 (human) for the full system, while the ablation Table E.1 gives 8.48 for the same system. The abstract says 10 narrative indicators; the paper defines 9.
- DOME: Table 1 and Table 2 give different human scores (Table 1 average ranks 1.15 to 1.77; Table 2 scores 1.20 to 1.32).
- ConStory-Bench: human-expert F1 is 0.229 in the table and 0.281 in the text, and recall is 0.139 in the table and 17.1% in the text. Group Relative Rank values also differ between text and table (GPT-5 3.05 against 2.80; Claude 4.9 against 4.54).
- Spoiler Alert: section 6.2 reports late no-rate 0.702 and 0.577 for the pipeline, while Table 2 reports 0.747 and 0.606.
- MAGNET: the rubric values in the text and the table disagree in places. The p-values for the three ablation rows are inferred from a list in the extraction and need checking.
- StoryScope: Gemini 3 Flash repeatability is reported as α = 0.88 in one place, 0.90 in another, and κ 0.89 in a third.
- Flawed Fictions: the paper is cited as 2025-04 in the notes, with no specific day given.
- Sudowrite: a blog says a Story Bible holds 2,000 characters per bible, while the May 21, 2024 changelog says unlimited. The changelog is the more recent primary source; the current limit is unverified.
- tell_me_a_story (Google DeepMind): the sidebar says Apache-2.0 and the README says CC-BY-4.0 for the dataset. The notes call this a conflict and do not resolve it.
- Fair-play detective Table 1 was garbled in extraction, so the per-model S_S, S_C, S_FP and ERC values are not reliable.

**Corrections to the brief.**
- **MAGNET's title.** The brief lists this work as "MAGNET and Atlas". The arXiv title is "From Personas to Plot: Character-Grounded Multi-Agent Story Generation for Long-Form Narratives" (arXiv 2607.00918). MAGNET is the system. "Atlas" does not appear in the HTML text read. A search snippet describes an ATLAS hallucination checker, but that conflicts with the full text. Neither Atlas claim is used in this report. Check the PDF before citing either.
- **The fair-play paper.** Wagner, Keydar and Abend (arXiv 2507.13841) do not propose a fair-play generation method. They propose a probabilistic framework and metrics for fair play and apply them to LLM-generated detective stories, where generation is plain paragraph-by-paragraph prompting with no clue planning and no checker. Cite it as an evaluation framework only.
- **"Book-Agent".** No pipeline by that name was found. The closest work is ReverieMem and the ICLR 2026 poster. If a specific project was meant, a link is needed.

**Commercial and open-source sources.** GitHub API access was refused in the research session, so star counts, licenses and commit dates come from rendered pages or secondary listings and are approximate. autonovel shows 3 commits on master, which suggests history was squashed or imported, and its license was not visible. InkOS's README was read in Chinese; the English README was not checked. The Inkfluence bible size of 5,000 to 12,000 words comes from a search snippet, not the primary page. The Inkfluence figures of 23,565 novels, "1-in-175" and "1,509 of 2,406" are self-reported and internal, and the vendor page itself says one test cannot yield a rate. The NovelCrafter "Progressions" feature is cited only from a competitor's comparison page and is unverified. Sudowrite's Write context limit is unconfirmed. Repo entries for StoryWriter, CreAgentive and novelai were not checked on GitHub.

**Engineering sources.** The Anthropic prompt-caching, rate-limit and batch pages are undated and were read on 2026-11-22; their prices and tier limits will change, and must be re-checked before any budget is set. Mem0 and Zep figures are from abstracts and are vendor-authored. Cognition is a vendor blog. The judge-bias paper ("Justice or Prejudice") was read at abstract level only, so its bias list and effect sizes are unverified. Lost in the Middle (Liu et al., 2023), MT-Bench, LangGraph, CrewAI and AutoGen were not fetched. Exponential backoff with jitter was not confirmed from the docs read; the rate-limit page only says to honour `retry-after`.

**Scope limits.** Most evidence is at 10 to 100 pages or about 7,000 words, English only, and drawn from tools and benchmarks built for general narrative. Nothing in the set addresses grimdark tone, serialised continuity across books, or novel-length consistency. Where a result looks directly applicable, it should be treated as a hypothesis to test on our own approved chapters.
